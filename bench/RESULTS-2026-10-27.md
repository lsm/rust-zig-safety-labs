# Rust vs Zig AI coding and safety experiments — 2026-10-27

**Status:** completed empirical pilot, with measured compiler logs and source artifacts.
**Repository:** `lsm/rust-zig-safety-labs`; independent experimental branch
`experiment/ai-comparison-v2`. This report does **not** prove language-wide
correctness, readability, Rust-equivalent safety, or a universal AI ranking.

## Goal

Determine whether a low-cost restricted Zig development workflow can preserve
Zig's straightforward programming style while reducing memory/concurrency
hazards and helping AI produce correct code, compared with plain Zig and safe Rust.

## What was actually run

- 10 deterministic short byte-array programming tasks (including bounded owned
  memory and two real OS threads), 15 held-out input vectors per task.
- Same exact coding model within each batch, two seeds per task per language,
  fresh stateless requests, identical behavior specs, separate language-specific
  syntax requirements and a fixed compiler/runtime judge.
- Zig 0.17.0 in Debug and ReleaseSafe; safe Rust 2021 in rustc.
- At most one AI correction after compilation, policy rejection or missing
  required structural signal. Test-vector failures did **not** expose oracle data
  to model repair prompts.
- Source, model digest, prompts, seeds, partial failures, compiler logs and
  generated code are preserved in GitHub Actions artifacts. Some tests use
  lexical checks for expected allocation and real-threading constructs; this is
  evidence, **not proof** that the requested behavior occurred.

### First-generation results

| Model and policy | First-pass correct | After at most one AI repair | Initial compiler errors | Initial policy rejections |
|---|---:|---:|---:|---:|
| Qwen2.5-Coder 1.5B — plain Zig | 7/20 | 7/20 | 11 | 0 |
| Qwen2.5-Coder 1.5B — strict Zig | 5/20 | 5/20 | 0 | 14 |
| Qwen2.5-Coder 1.5B — safe Rust | 0/20 | 0/20 | 20 | 0 |
| **Qwen2.5-Coder 3B — plain Zig** | **5/20** | **6/20** | 13 | 0 |
| **Qwen2.5-Coder 3B — strict Zig** | **5/20** | **6/20** | 5 | 10 |
| **Qwen2.5-Coder 3B — safe Rust** | **15/20** | **15/20** | 3 | 0 |
| Qwen2.5-Coder 3B — pragmatic indexed Zig | 3/20 | 4/20 | 12 | 4 |

The 1.5B model frequently confused Rust and Zig syntax: **14 of 20 Rust
initial candidates had obvious Zig-style `@import` or `[]const u8` constructs**,
and all 20 Rust candidates failed compilation. Those outcomes reflect model
failure and a language-mixing prompt confounder. Do not claim Zig intrinsically
beats Rust from that batch.

For 3B, separate Rust/Zig system prompts were supplied with minimal unrelated
syntax examples. All 60 original 3B trials were judged. The 3B first-pass paired
outcomes were:
- Plain Zig vs strict Zig: 1 plain-only pass, 1 strict-only pass, 18 ties.
- Rust vs plain Zig: 11 Rust-only passes, 1 plain-only pass, 8 ties.
- Rust vs strict Zig: 11 Rust-only passes, 1 strict-only pass, 8 ties.

With only 20 trials per arm and a deliberately small coding model, differences
remain model-, task-, and prompting-specific. Simple Wilson 95% intervals on 3B
first-pass pass rates are roughly: Rust 53.1%–88.8%, plain Zig 11.2%–46.9%,
strict Zig 11.2%–46.9%. These intervals do not capture task-selection bias.

### Low-cost Zig interventions (measured separately, not additive)

| Intervention on Qwen 3B Zig | Before | After | What was held constant |
|---|---:|---:|---|
| Permit direct checked indexing | 5/20 | **5/20** | Same exact 20 previously generated strict-Zig files, only policy changed |
| Generate new Zig with pragmatic checked-index guidance | 5/20 strict comparator | **3/20** new pragmatic samples | Same 3B model and task set; policy **and** prompt differed, so not a pure policy effect |
| Transparent old-syntax repairs, plain Zig | 5/20 | **9/20** | Same exact 20 model files; no model regeneration |
| Transparent old-syntax repairs, strict Zig | 5/20 | **7/20** | Same exact 20 model files; original strict policy still enforced |

The **syntax repair** is an auditable sequence of deliberately small operations:
modernize one old `for (container) |value, index|` capture form, convert a
limited old `@intCast(Type, value)` form, and add a missing standard-library
import (plus optional trusted core import normalization). All changed candidates
are then recompiled in real Zig tests. The fix does **not** relax ownership or
concurrency restrictions. It is not a generally correct Zig transpiler.

On the frozen 3B outputs, 9 plain-Zig candidates and 9 restricted-Zig
candidates were changed by these explicit rules. **4** previously failing
plain-Zig examples and **2** previously failing strict-Zig examples passed
afterward. A policy-only relaxation yielded **zero** newly correct samples.

## Security: what the experiments do and do not establish

**Safe Rust** rejected examples of use-after-free and conflicting mutable
borrows at compilation. In the 3B AI batch, a Rust thread-lifetime error was
also rejected before execution. This is meaningfully stronger than Zig's
default static lifetime and race checking, within Rust code that does not use
`unsafe` or unchecked FFI.

**Strict Zig** rejects application-level allocations/frees, raw pointer
operations, direct thread operations and direct indexing via a conservative
lexical rule checker, with a separately trusted core implementing owned-copy
and split-thread operations. **Pragmatic Zig** additionally allows slice
indexing but **requires both Debug and ReleaseSafe checks**, keeping runtime
bounds traps. Neither Zig mode provides formal guarantees about dangling
references or thread races in its trusted core. The trusted benchmark core is
approximately **40 nonblank non-comment source lines** and must be counted
when assessing maintenance cost.

In the first safety round, 13 deterministic cases behaved as expected; two
Zig UB cases were only observations, **not safety confirmations**. The nine
subsequent hand-coded controls passed real compiler/held-out-vector smoke tests,
but those are not AI generation samples.

## Readability, writing effort and scope

For the 3B first drafts, mean candidate nonblank source LOC were approximately
**Rust 8.5**, **plain Zig 12.4**, **strict Zig 12.0** and **pragmatic Zig 12.2**.
These are descriptive proxies, **not** measurements of subjective readability.
The reusable trusted Zig core and checker development are excluded from
candidate LOC. No independent reader/user study was performed.

A key real-world confounder is model training familiarity: many 3B Zig compiler
errors arose from outdated Zig syntax (index captures and two-argument
`@intCast`) or missing imports, not fundamental memory unsafety. This is part
of present-day AI tooling performance, not proof of an intrinsic language flaw.

## Conclusion and direction

1. **For this scoped AI model and these tasks, safe Rust was substantially more
   reliable on first pass (15/20 vs 5/20 for both original Zig arms), and its
   compiler provides stronger static memory/thread safety guarantees.**
2. **A small restricted Zig API and CI workflow can deny several classes of
   dangerous application code cheaply**, but our trial did not find an AI
   correctness advantage. Restriction alone was not enough.
3. **Version-aware, deterministic Zig syntax repair was the highest-return
   low-cost AI intervention observed so far** (plain 5→9; strict 5→7), without
   pretending to solve lifetime and race errors.
4. Next research: use a substantially more capable **fixed** code model across
   many real codebases; repeat prompts with a preregistered task set; use an AST
   or compiler-plugin policy gate; fuzz/sanitize the Zig trusted core; and run
   blind human readability reviews. Until then, recommend Rust for strongly
   safety-critical AI-written concurrency and use Zig safe-subsets only with
   clearly documented limits and mandatory CI.
